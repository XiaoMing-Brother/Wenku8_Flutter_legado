# 替换净化、在线字典与 TXT 目录规则

阅读器支持三类与 Legado 兼容的可选规则库，数据独立保存在应用支持目录，不写入书源 JSON 或离线正文缓存。

## 替换净化

- 入口：`设置 → 替换净化`；阅读器设置的主题分类中可单独关闭当前书籍的替换。
- 字段与 Legado `ReplaceRule` 对齐：`name`、`group`、`pattern`、`replacement`、`scope`、`excludeScope`、`scopeTitle`、`scopeContent`、`isEnabled`、`isRegex`。
- `scope` / `excludeScope` 判断范围文本里是否包含当前书名或书源 URL，不匹配作者、书源显示名或截短的 URL。例如 `书甲,书乙` 对两本书都有效。留空 `scope` 表示全部，排除优先；本地书的来源是 `loc_book`，缺失的书名或来源不参与匹配。与 Legado 的 SQLite `LIKE` 一样，ASCII 字母不区分大小写，书名或来源自身带有的 `%`、`_` 分别匹配任意长度和单个字符。
- 标题（含卷名和目录）和正文开关独立，现代 JSON 未指定时分别默认关闭、开启。普通文本和正则规则都支持，正则替换可用 `$1`、`$&`、`$0`、`$$`。
- 按 `order` 升序依次处理上一条的结果，旧版规则读取 `serialNumber`。显式序号（含零和负数）在导入、更新、导出后保留；同序规则保持原相对顺序。现代 JSON 无序号的新规则追加在末尾，已有规则保留原位。拖动后以新顺序执行。
- 规则只改变阅读页显示，不改写缓存正文、原始文件或阅读坐标；关闭规则后立即恢复原文。
- 在「阅读设置 → 净化 → 生效的替换」关闭单条规则或分组，本次阅读的正文、章名和目录会按剩余规则重新显示。切章或关闭设置不影响临时选择；退出阅读页后恢复，不影响其他书。全局已停用的规则不能在此临时开启；永久修改请用「管理替换规则」。
- `@js:` 替换脚本暂不支持，保存时会提示改用普通文本或正则分组。

## 在线字典规则

- 入口：`设置 → 字典规则`，或阅读查词弹窗中的「在线字典规则」。
- 字段与 Legado `DictRule` 对齐：`name`、`urlRule`、`showRule`、`enabled`、`sortNumber`。
- 首次启动会写入 Legado 默认规则：汉典、海词英文。
- `urlRule` 支持 `{{key}}` 和书源同款请求/规则表达式；`showRule` 复用 Android 原生书源分析器、Jsoup、JSONPath、XPath、正则和 Rhino。
- 查词结果与离线 MDX/MDD、StarDict、MOBI 词典合并显示，在线规则失败不会阻止离线结果。
- 字典规则需要 Android 原生引擎；其他平台仍可使用离线词典。

## TXT 目录规则

- 入口：`设置 → TXT 目录规则`；也可在 `本地 → 显示与筛选 → 更多本地设置 → 导入与目录 → 自定义规则 → 选择规则` 中直接选用。
- 字段与 Legado `TxtTocRule` 对齐：`id`、`name`、`chapterRule`、`volumeRule`、`example`、`serialNumber`、`enable`；旧字段 `rule` 也可读取。
- 首次使用会写入 Legado 默认规则。规则可搜索、启停、拖动排序、新增、编辑、删除，也可从剪贴板或 JSON 文件导入、导出回剪贴板。
- 测试页会逐行显示命中的卷名和章名，并按 Legado 的自动选择算法给出建议：至少 2 个章节样匹配，且相邻匹配间隔超过 1000 字符；命中数相同时优先使用排序靠前的规则。
- 「导入与目录」支持「规则库自动匹配」：导入 TXT 前读取开头样本，从已启用规则中选择，选中规则的章节、分卷表达式会随该书目录设置保存；没有合适规则时退回内置自动识别。也可手动选择一条规则并写入当前导入设置。
- 目录设置只影响之后导入的书，既有目录、阅读位置和书签不会重写。
- 匹配使用原始行并在前面补一个换行边界，因此 `(?<=\\s)` 一类 lookbehind 规则可以工作；章名展示时再去除首尾空白。单行标题限制为 90 个字符。

## 数据位置

- 替换规则：应用支持目录 `/reader-replace-rules/rules.json`
- 字典规则：应用支持目录 `/reader-dict-rules/rules.json`
- TXT 目录规则：应用支持目录 `/reader-txt-toc-rules/rules.json`

## 已知边界

- 替换规则没有 Legado 的正则执行超时保护，复杂表达式可能拖慢当前章节。
- Flutter 正则与 Java/Kotlin 正则存在少量语法差异；导入时会校验明显无效的表达式。
- 在线字典规则只执行用户主动发起的查词，不会预取或批量请求。
- TXT 目录按行识别，依赖下一行/跨行上下文的正则无法完整复现；不支持或无效的规则会在列表中提示，并跳过启用匹配。
